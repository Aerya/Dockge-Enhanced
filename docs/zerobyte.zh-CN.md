# Zerobyte（可选）

[English](zerobyte.md) · [Français](zerobyte.fr.md) · [Español](zerobyte.es.md) · [Deutsch](zerobyte.de.md) · [简体中文](zerobyte.zh-CN.md)

在 **备份** 中启用 **Zerobyte（可选）**。关闭会折叠整个区域，但保留配置、凭据、容器和备份数据。Enhanced 原生 Restic 的覆盖范围、仓库和保留策略维持不变：**不会自动排除或迁移任何内容**。

## 现有实例

填写 **Enhanced 服务器能够访问的** HTTP(S) 源地址，以及在 Zerobyte 设置中生成的 API 密钥。URL 不允许包含凭据、查询参数或路径。保存后测试连接。Enhanced 不管理外部实例的 Docker 资源。关联实例摘要仅供读取；受保护的 Stack 钩子适用于下述托管工作流。

## 托管安装

Enhanced 在自己的 Stack 目录中生成普通 Compose 项目。项目名根据 Enhanced 实际的数据和 Stack 挂载路径生成，避免多个实例冲突。两个目录都必须是可识别的主机 bind mount。Zerobyte 使用官方镜像 `ghcr.io/nicotsx/zerobyte:v0.43.2`，采用降低权限的安装方式：不使用 Docker socket、SYS_ADMIN 或 FUSE。内部数据库/配置及恢复暂存区使用自动创建的持久化命名卷；切勿将这些卷选为来源或目标。

1. 添加至少一个现有主机目录或现有 Docker 命名卷作为 **来源**。验证后 Enhanced 会显示 `/sources/local-…` 路径。来源为只读。
2. 添加至少一个独立的现有主机目录作为 **目标**。其可写路径位于 `/destinations/store-…`。对于主机挂载的 NFS/SMB/SSHFS/rclone 共享，请选择 **此目录必须是已挂载的远程共享**。声明的共享缺失时会拒绝操作。
3. 出现提示时，确认它与 Enhanced 远程 Restic 仓库相互独立。Enhanced 无法证明 S3/SFTP/REST 存储与主机挂载共享不同。本地仓库（包括禁用的目标）会在主机命名空间中自动检查。
4. 选择空闲本地端口，使用 `http://127.0.0.1:<port>`，然后确认安装。界面仅监听回环地址；从其他计算机访问时使用 SSH 隧道。Enhanced 加入项目网络；连接字段使用实例专属的服务别名。替换 Enhanced 容器后必须保留该网络连接。
5. 打开 Zerobyte，完成初始设置，安全保存恢复密钥并生成 API 密钥。将 API 密钥填入 Enhanced 并保存连接。
6. **挂载不会创建逻辑卷、仓库或备份任务。** 在 Zerobyte 中按显示路径创建 Directory 来源，在目标路径下创建 Local 仓库，然后创建任务。通过 Enhanced 创建的任务默认禁用。计划和保留策略在 Zerobyte 中设置。

包含符号链接、路径遍历、系统/控制根目录、来源和目标的共同祖先关系、嵌套目标、bind 别名，或与 Enhanced 数据、Zerobyte 内部数据及 Enhanced 本地 Restic 仓库重叠的路径都会被拒绝。主机目录通过临时只读、禁用网络的检查容器验证；移除其他能力后仅保留 DAC_READ_SEARCH。每次启动 Zerobyte 都会检查目标文件系统身份。共享消失或被替换会阻止启动，不会写入其本地备用目录。主动更换存储后应重新验证挂载。Docker bind mount 在运行时保持挂载文件系统的引用；共享不可用可能导致 I/O 出错或阻塞。这并不保证网络可用性。

重复应用相同安装设置会复用项目和卷。更改挂载前，先配置 API 连接，禁用所有 Zerobyte 任务并等待正在运行的操作结束。明确确认挂载更新；替换失败会重新应用旧 Compose 文件。更改挂载后检查已有逻辑任务。未提供卸载或删除卷的端点。请保密保存生成的 `.env` 和 `.zerobyte.json`；它们用于所有权验证和持久配置。首次部署失败时会保留卷和元数据，以便重试或诊断。

## 操作与恢复

概览仅显示任务、仓库、逻辑来源和活动操作的允许字段；未知统计值仍显示为未知。备份和保留清理均需明确确认。保留清理可能按该任务自己的策略删除 Zerobyte 快照，绝不会调用 Enhanced Restic 维护。

托管恢复会自动验证 `/restore-test`；外部恢复需要 **已验证的专用根目录，并针对该 URL 和 API 密钥明确批准**，详见下文。切勿将此设置指向应用数据或来源/目标目录。每次请求生成随机子路径，禁用删除并将覆盖设置为 `never`。恢复为异步操作；使用文件前应在 Zerobyte 确认任务完成。外部实例的暂存挂载必须由操作员独立验证。

密钥保存在服务器端 `zerobyte-settings.json`（权限 0600），不会返回浏览器，不会放入 URL 或上游错误消息。界面和管理端点使用 Enhanced 现有 HTTP 身份验证策略；范围受限的 pre/post 回调端点改用各工作流的专属密钥。与 Enhanced 其他功能一样，禁用身份验证会移除该保护。请求限制执行时间和响应大小，并拒绝重定向。

## 受保护工作流向导

托管安装提供 **受保护备份向导**：选择一个已挂载来源、一个目标、名称、cron 表达式及期限（1–120 分钟）。检查准确计划后确认。它使用 Zerobyte 实际 API 创建或复用 Directory 来源、独立 Local 仓库及禁用的任务。Zerobyte 在显示的仓库父目录下添加自己的仓库 ID。持久所有权记录使重试具备幂等性；冲突的已有资源会被拒绝，绝不删除。复用计划不会悄悄更改策略。需要不同停止策略或期限时，请使用新计划名。

这些任务会配置官方 pre/post HTTP Webhook，并使用服务器端的工作流专属密钥，手动和计划执行均适用。生成的 Compose 允许列表仅放行所属 Enhanced 的回调源地址。替换 Enhanced 时保留 `enhanced-<owner>` DNS 别名和共享网络；重新应用安装器会修复回调别名。

停止应用前，pre-hook 检查主机挂载可用性和文件系统身份，然后在目标内执行有时间限制的写入/fsync/删除探测。备份期间监视器定期检查。存储失联或期限到达时，Enhanced 请求取消，仅重启原本运行的服务，并记录持久故障。绝不以本地目录替代目标。单独配置的本地备份计划是明确的替代方案；不存在隐式本地回退或稍后自动转移。

中断的工作流保持暂停，直到明确确认远程任务已进入终态。请求取消不等于证明远程进程已经停止；未检查前请勿信任中断执行产生的快照。界面打开时会刷新状态；配置的备份 Discord/Apprise 目标可用时也会收到故障通知，但通知送达本身不受保证。

可选的 Stack 停止范围仅限本 Enhanced 实例 Stack 目录中的托管 Compose 文件，并检查 Docker 标签所有权。这些钩子不能停止 Enhanced 或 Zerobyte。停止前会将运行服务列表写入恢复日志；准备失败、备份失败、post-hook 丢失或 Enhanced 重启后均可据此恢复。服务重启失败会保留日志并阻止原生备份/恢复，不会默默宣称恢复成功。原生 Restic 设置、排除项及保留策略不变；仅通过进程内互斥防止原生操作与应用停止发生竞争。这不能阻止操作员独立修改容器，也不能保证 Docker 或主机不可用时恢复。

直接在 Zerobyte 或高级任务表单创建的任务，没有 Enhanced 工作流钩子，除非明确通过向导配置。界面会相应标识。其原生调度和网络行为由 Zerobyte 负责。受保护向导创建的任务不启用自动保留清理；手动清理仍需确认。操作员之后直接在 Zerobyte 添加保留策略时，Zerobyte 原生自动维护会生效；Enhanced 不拦截第三方配置变更。

## 外部连接与联合

外部配置包含明确警告和与 URL **及 API 密钥**绑定的确认，任一变更都会撤销确认。只读状态/连接测试仍可使用；连接不是已验证归属的托管 API 源地址时，修改操作需要确认。明确保存专用根目录前，外部恢复保持禁用；原有全局环境变量不会启用它。恢复时会对已知逻辑来源和本地仓库路径进行词法重叠检查，但 Enhanced 无法证明外部文件系统布局、符号链接解析或物理隔离。托管恢复则自动验证自己拥有的专用可写 Docker 卷，拒绝与其他挂载存在卷别名的情况。

关联实例视图通过现有已认证联合传输汇总允许的只读计数，从不传输 Zerobyte 密钥，并区分集成禁用、Zerobyte 不可达及对端离线/不兼容。远程操作仍在所属实例执行。开发验证不使用运行中的生产对端。

### 诊断与已有任务迁移

外部诊断仅读取 API：配置、资源清单、已知路径隔离和任务间共享仓库。物理挂载、符号链接、远程身份、实际权限及独立恢复演练仍需操作员明确检查。通过 API 检查绝不认证这些属性。

先在 Zerobyte 禁用已有任务，等待活动操作结束，再在向导中选择 Stack 和期限。预览并确认迁移。仅修改钩子和自动重试次数；来源、仓库、快照、计划、过滤条件及保留策略保留，任务仍禁用。已有自定义钩子和任务间共享仓库会被拒绝。API 响应不确定时，保持任务禁用并重试相同计划以验证迁移。

应用恢复状态与备份结果分开显示。Docker 无法重启服务时保留恢复日志并重试。请检查 Docker 和指定 Stack；应用恢复不代表备份成功。每次停止前日志都会同步到磁盘。

### 故障演练

使用仅含虚构数据的专用共享和 Stack。先验证备份及恢复内容。分别注入 TCP 丢失、服务器停止、撤销权限、只读共享和空间耗尽，检查执行前拒绝和持久告警。也要在执行中断开存储，检查取消、任务实际终止，以及仅恢复原先运行的服务。

模拟 Docker 故障时，使用测试实例专用的 Docker socket 中继，不要停止与生产共享的 daemon。突然重启测试容器可以验证持久恢复，但不等同于主机物理断电测试。联合测试应使用隔离实例、身份验证拒绝和旧版本。

存储检查采用固定探测名称和每目标本地锁，限制阻塞在 NFS hard 系统调用中的探测。Enhanced 超时无法强制中断不可中断的内核操作，仍可能需要恢复服务器。重复工作流告警最多每五分钟通知一次。联合认证被拒绝后，请明确重新认证 agent；仅重新启用远程账户不会重启因安全原因停止的传输。

### 任务完整性与手动应用恢复

Enhanced 在手动启动前、pre-hook 内，以及没有活动应用备份时约每分钟检查已注册任务。回调 URL/认证、来源、仓库和重试设置必须与工作流一致。保护缺失、改变或无法验证会阻止从 Enhanced 启动；修正后可以立即验证。绝不会悄悄替换钩子。删除所有钩子并直接在 Zerobyte 启动会绕过拦截；应保持监控和钩子启用。

恢复失败会列出日志记录的 Stack 和服务。手动重试仅在远程任务终止后重启这些服务，绝不会启动另一份备份，也不会将中断备份标为成功。

### 明确重新验证存储

禁用所有任务，结束活动操作，并实际核实服务器、共享和仓库隔离。预览指纹变更，声明已检查并确认。同意绑定准确的计划修订版；变更后必须重新预览。

文件系统保护以代码 31 停止 Zerobyte 后，Enhanced 可只读访问其已验证专用 Docker 数据卷中的数据库。所有任务必须保持禁用，活动操作必须结束。停止进程后，Enhanced 再次检查资源清单和挂载，之后才替换保护配置。旧 Compose/元数据文件保留在私有 `.pre-revalidation` 副本中。仅重新部署 Zerobyte；已声明的远程目标不能变成本地备用目录。

联合会区分已知认证拒绝、对端断开、不兼容响应和超时。仅超时不能证明版本过旧，应检查连接和兼容性。参见 [可重复实验室演练](../extra/zerobyte-lab/README.md)（英文）。
