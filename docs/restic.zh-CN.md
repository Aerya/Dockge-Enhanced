# Restic 备份与恢复

[English](restic.md) · [Français](restic.fr.md) · [Español](restic.es.md) · [Deutsch](restic.de.md) · [简体中文](restic.zh-CN.md)

Dockge-Enhanced 在**备份**页面中内置原生 [Restic](https://restic.net/) 引擎。它独立于可选的 [Zerobyte 集成](zerobyte.zh-CN.md)，后者使用自己的仓库和保留策略。

## 备份内容

- 每个已包含 Stack 的 `compose.yaml`、override 和 `.env` 文件。可在**要备份的堆栈与一致性**中将某个 Stack 从所有备份中排除。
- 可选数据路径：`/app/data`（Dockge-Enhanced 数据），以及挂载到 Enhanced 容器中的任意数量的卷（例如 `/dockers-data`），在**要备份的 Docker 数据卷**中选择。大小按需计算。
- 内置排除项（`*.log`、`__pycache__`、`node_modules`）始终生效；自定义 glob 模式会传给 `restic --exclude`。

请完整备份 `/app/data` 目录，包括 `two-factor.key`：仅恢复数据库而没有这个密钥，将无法解密 TOTP 密钥。

## 目标与计划

- 目标：本地、SFTP/NAS（SSH 密钥或密码）、S3/Backblaze B2 和 REST Server。可以同时启用多个目标，每次运行都会备份到所有目标。
- 使用本地目标时，请挂载一个专用主机目录，例如 `../../backup/dockge:/backup`，并将目标路径设为 `/backup`。
- 支持计划备份、**立即备份**以及保存 Compose 时备份。保存时创建的快照带有 `on-save` 标签，有 60 秒冷却时间，并有意跳过 `restic forget`，因此连续多次保存永远不会删除较早的每日或每周快照。
- 默认启用的重叠保护会在另一个 Restic 备份运行时，阻止手动、计划或保存时触发的备份启动。
- 每次备份和保留清理之前，都会用 `restic unlock --remove-all` 删除过期的 Restic 锁。退出码 3（某个源文件无法读取）会被记录为带警告的成功。

## 按 Stack 的一致性

每个已包含的 Stack 都有自己的模式：

- **实时**：不中断。
- **先停止再启动**：快照前只停止正在运行的服务，之后重启相同的服务，即使失败也会重启。
- **应用钩子**：前置/后置命令通过 `docker compose exec` 在所选服务内运行，例如导出数据库，无需访问主机 shell。

Stack 会在保留清理和恢复测试之前重新启动，以尽量缩短停机时间。

## 设置、保留与维护

- **保存**只保存设置和保留策略，不会运行备份或清理。
- **立即备份**会立即运行备份，成功后再执行普通保留策略。
- 维护工具会刷新仓库和快照状态，并对每个已启用目标运行 `restic check`。
- 普通保留策略（`keepLast`、每日、每周、每月）在成功的计划或手动备份后执行，不会在保存时备份后执行。
- 在受保护的 Dockge-Enhanced 自更新之前创建的强制快照使用独立的保留策略：新快照创建**并通过校验**后，保留本安装最近的两个自更新快照。稳定的安装标签可确保清理不会影响共享同一仓库的其他实例。如果该清理失败，已校验的备份仍会保留。
- 快照列表默认显示**全部**。当最近一次成功备份的时间超过配置间隔的两倍时，会显示 **备份已逾期** 标记，并在每个间隔发送一次通知。

## 仓库初始化

首次备份时，Restic **只会初始化确认不存在的仓库**。访问、网络和密码错误会阻止初始化，而不会创建新仓库。界面会显示每个已启用目标的仓库状态。

## 仓库与备份源重叠

最好将本地 Restic 仓库放在所选备份文件夹之外。

- 如果本地仓库位于某个已选择的备份源之下，保存设置时会显示警告，备份会自动排除该仓库、其重置归档以及它的其他 Docker 挂载路径。解析后的符号链接也会被检查，已停用的本地目标仍受保护。
- 例如，可以继续选择 `/app/data`，同时仓库位于 `/app/data/backups`。
- 不允许把仓库本身或其子目录选为备份源。每次备份前都会再次检查路径。
- 此检查绝不会移动或重置仓库。现有路径、密码和保留设置都会保留。

## 安全重置仓库（Local、SFTP、S3 和 REST）

在**备份 → 维护与诊断**中选择一个已启用目标，预览其仓库和快照数量。

- 重置需要两次明确确认、准确的确认短语和一个短期有效的一次性令牌。
- 本地仓库会先重命名为保留的归档，再创建新仓库。远程仓库会切换到新的 SFTP 目录、S3 前缀或 REST URL；旧仓库不会被删除。
- 新的活动仓库不包含旧快照。只会删除该目标的近期历史记录。
- 旧仓库保留在原位置以便恢复：这**不是**对备份数据的永久删除。
- 如果仓库由其他客户端共享，请先与它们协调，再进行重置。

## 恢复与校验

- 快照浏览器会并排列出 Compose、`.env` 和卷文件，并显示它们与上一快照相比的状态（新增 / 已修改 / 未变）以及与当前磁盘相比的状态（一致 / 已修改 / 缺失）。
- 恢复前可以预览文本文件，并与磁盘或上一快照进行比较。
- 可以恢复任意选择的文件，也可以通过**恢复堆栈**恢复整个 Stack。
- 每次计划备份后，恢复测试会从新快照中读取一个真实文件，并将结果记录到备份历史中。使用**检查完整性**可运行完整的 `restic check`。
- 受保护的自更新和恢复流程都依赖这些经过校验的 Restic 快照。

## 选择自更新前的备份方式

更新 Enhanced 前有三种选择：Restic（默认）、Zerobyte 备份并验证，或确认数据丢失风险后不进行更新前备份。最后一种模式下，Enhanced 不会执行或验证任何备份，也不要求提供外部备份证明。使用 Zerobyte 时，专用任务必须成功完成，且新快照必须包含本次更新的恢复文件；失败或超过 30 分钟会阻止更新。镜像回滚不会恢复已修改的数据。

在备份页面配置 Zerobyte。使用专用任务：来源为挂载到 Zerobyte 的完整 Enhanced 数据目录，不使用过滤器、钩子、计划或重试。Enhanced 验证新快照；失败或超过 30 分钟时阻止更新。保留策略仍由 Zerobyte 管理。
