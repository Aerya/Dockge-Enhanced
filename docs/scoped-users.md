# Restricted local accounts

Administrators configure accounts under **Settings → Security → Users and permissions**, with local authentication enabled. Existing accounts remain administrators after the database migration. New accounts are restricted, active only when selected, and receive no grants by default. This screen cannot promote an account or edit an administrator. Restricted users manage their own password, TOTP and recovery codes in **My account**. Password changes require the current password and a valid second factor when enabled. Administrators can reset a restricted account's password, disable it, reset its 2FA or delete the account without deleting any stack/data. Resetting 2FA/deleting requires administrator reauthentication and explicit confirmation. Other sessions are disconnected after security changes. Trusted-proxy identities map to the local account with the same username: an account that is restricted limits that proxy user, and an administrator account keeps full access. A proxy identity without an account is created as restricted with no grants (fail closed), except the first user of a fresh installation and identities listed in `DOCKGE_AUTH_PROXY_ADMIN_USERS` (comma-separated), which become administrators. Existing accounts keep their stored role, so upgrading never demotes an administrator. Restricted proxy users can use the socket workspace but not protected HTTP APIs. Proxy user records are cached for 30 seconds, so a role or disable change can take up to 30 seconds to apply to proxy sessions.

Optional service grants use the exact Compose service name and cover its replicas, including replacement containers. A service grant does not grant access to sibling services or whole-stack actions. Whole-stack grants include all services: uncheck the whole-stack entry to restrict access to selected services. Service starts use `--no-deps`; actions involving network-namespace dependants fail closed and require an administrator or an explicitly granted whole-stack action. Direct and reverse peers use a separate service RPC, so an older peer cannot interpret a service action as a whole-stack action. No fallback to the whole-stack RPC is permitted. A nonexistent or renamed service fails closed.

Each grant identifies an exact **instance endpoint + Compose stack name** and contains independent view/logs/start/stop/restart/update/recreate permissions. View is mandatory for a selected stack. No wildcard or inherited grants exist. Review grants before reusing a stack name or replacing a linked endpoint: names are not immutable resource identities. The logs permission exposes a bounded snapshot (200 lines per service, at most 1 MiB); application logs can contain secrets. Grant update/recreate only to trusted operators: those actions execute the administrator-maintained Compose, not an editable user-supplied definition.

Restricted users get a dedicated workspace. Compose, .env, terminal, file browsers, deletion, resource cleanup, backups, settings, API-token creation and federation administration remain administrator-only. A default-deny Socket.IO gate rejects the raw agent proxy and all other administration events. Existing protected HTTP APIs reject restricted login JWTs. Restricted sockets do not subscribe to shared federation broadcasts or administrator rooms. Permissions are checked on the server, not just by hiding buttons.

For linked instances, update both hub and node. The hub authorizes the exact endpoint and stack before using an authenticated administrator federation transport; the node executes a narrow RPC with sanitized responses. Direct and reverse agents use the same policy. An old/offline node fails closed instead of falling back to unrestricted proxy calls. No restricted user credentials are sent to nodes. Only an administrator may establish or revoke federation. A node can still be controlled independently by its own administrator.

Editing grants or disabling an account disconnects its sessions. Reconnection reloads current permissions; disabled accounts cannot reuse their JWT. A request's result is checked again before delivery. Revocation is not cancellation: an already dispatched Docker operation is allowed to finish, and a timeout does not prove it failed. Inspect the stack before retrying. Mutations of the Enhanced management container itself are denied. Read-only status checks and scoped logs remain available when granted.

## Validation

**Downgrades:** an older Enhanced image does not understand these roles. Disable every restricted account before restoring an older image or database snapshot into such an image. The migration's explicit schema rollback disables restricted accounts, but simply switching Docker images does not run that rollback and cannot provide this protection. Never use an old version with active restricted accounts.

`npx tsx --test backend/user-access.test.ts` covers permission parsing and a real Socket.IO default-deny transport. The opt-in integration script `extra/scoped-users-smoke.ts` starts two native servers with temporary databases and random credentials on loopback ports. It deploys uniquely labeled, volume-free fixtures through Dockge, exercises local/direct/reverse permissions and revocation, then removes those fixtures and temporary data. It requires a built frontend, a working Docker installation, an existing `busybox:stable` image and an explicitly supplied `DOCKGE_TEST_SELF_CONTAINER` (inspected only as the self-protection reference). It never performs a global Docker prune.
